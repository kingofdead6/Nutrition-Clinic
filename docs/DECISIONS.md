# Decisions and deviations from the spec

Running log of choices made while building, and why. The spec itself is in [SPEC.md](SPEC.md).

## Phase 1

| #   | Decision                                                                                                                                                                                                                     | Why                                                                                                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Folders are `apps/client` and `apps/server` (spec said `apps/web`).                                                                                                                                                          | Requested by the owner.                                                                                                                                 |
| 2   | Patient `status` is **stored** and recomputed on every plan/measurement/override change, plus a sweep at startup and once per day. `inactive` = archived, or no active plan and no visit in 60 days (`INACTIVE_AFTER_DAYS`). | `plan_ended` depends on the passage of time, and list filtering/pagination by status must happen in the database. The spec gave no rule for `inactive`. |
| 3   | Standalone Mongo has no transactions, so invariants live behind repository methods (`dietPlans.activate`, `importAll`) plus a partial unique index `one_active_plan`. SQLite will use real transactions.                     | Keeps business rules driver-agnostic.                                                                                                                   |
| 4   | Arabic search goes through `normalizeArabic()` (أ/إ/آ→ا, ة→ه, ى→ي, no tashkeel) into a stored `searchKey`.                                                                                                                   | Typing «فاطمه» must find «فاطمة». Works the same in SQLite with `LIKE`.                                                                                 |
| 5   | All timestamps are stored as ISO strings (UTC) and date-only fields as `YYYY-MM-DD`, with no `Date` objects in storage.                                                                                                      | Identical in Mongo and SQLite, sorts lexicographically, no conversion at the boundary.                                                                  |
| 6   | Mongo `_id` holds the UUID itself, mapped to `id` in `MongoCrudRepository`. Mongoose schemas declare only `_id` and indexes (`strict: false`); zod in `@clinic/shared` is the single source of truth for shapes.             | No duplicated schema definitions that could drift.                                                                                                      |
| 7   | Meal types are `breakfast, morning_snack, lunch, afternoon_snack, dinner`.                                                                                                                                                   | The spec listed "snack" twice.                                                                                                                          |
| 8   | Diet-plan items snapshot `foodName` and nutrition when saved; prescriptions snapshot all printed content. Templates are diet plans with `isTemplate: true, patientId: null`.                                                 | Editing the food DB or a template never changes an issued document.                                                                                     |
| 9   | "Today" is computed in the clinic timezone (`settings.timezone`, default `Africa/Algiers`).                                                                                                                                  | Correct day boundaries for appointments/status regardless of the host clock.                                                                            |
| 10  | The server can serve the built client (`CLIENT_DIST_DIR`), giving a single origin.                                                                                                                                           | The desktop app loads the UI from the local server, so the httpOnly cookie is same-origin (`SameSite=Strict` also covers CSRF).                         |
| 11  | Desktop port: a fixed preferred port with fallback to random (`PORT=0`), not always random.                                                                                                                                  | Browser storage and cookies are per-origin, and the port is part of the origin.                                                                         |
| 12  | Express 5, zod 4, TypeScript 6, Vite 8, Vitest 5, Mongoose 9. React 18, React Router 6 and Tailwind 3 pinned as specified.                                                                                                   | Current stable majors. Express 5 forwards rejected async handlers to the error handler.                                                                 |
| 13  | Dev client runs on Vite's default port **5173** with `strictPort` (was 5273 until the owner asked for the default). | `strictPort` keeps CORS predictable: Vite fails instead of silently moving to another port. |
| 14  | Custom zod messages are i18n keys (`validation.*`). Server error messages are keys too (`errors.*`), translated by the client.                                                                                               | Arabic messages without the server knowing the locale.                                                                                                  |
| 15  | The ESLint rule `no-restricted-syntax` rejects physical Tailwind classes (`ml-`, `pr-`, `left-`, `text-right`…) in `className`/`cn()`. `no-restricted-imports` blocks `mongoose` outside `repositories/mongo/`.              | Enforces the RTL and driver-isolation rules mechanically.                                                                                               |
| 16  | Tests use `mongodb-memory-server` pointed at the installed `mongod` (`MONGOMS_SYSTEM_BINARY`).                                                                                                                               | No binary download, so tests run offline.                                                                                                               |
| 17  | Planned: `bcryptjs` rather than native `bcrypt` (Phase 2).                                                                                                                                                                   | Same algorithm, no native build, so no `electron-rebuild` pain.                                                                                         |

## Change: JavaScript server (owner request, after Phase 1)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                               | Why                                                                                            |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 18  | `apps/server` is plain JavaScript (ESM). The run file is `apps/server/index.js`, started with `node index.js` (dev: `nodemon`). No tsx/tsup/tsc on the server.                                                                                                                                                                                                                         | Requested by the owner.                                                                        |
| 19  | Types stay available as JSDoc (`@typedef`, `@param`, `import('@clinic/shared').Patient`), so VS Code IntelliSense still works. The server has no typecheck step.                                                                                                                                                                                                                       | Keeps editor help without a TS toolchain on the server.                                        |
| 20  | Repository "interfaces" are JSDoc typedefs plus frozen method-name lists (`REPOSITORY_CONTRACT`). `createRepositories()` runs `assertRepositories()`, so an incomplete driver fails at startup, and the contract suite checks it too.                                                                                                                                                  | JavaScript has no interfaces; this keeps the swappable-driver guarantee enforceable.           |
| 21  | `packages/shared` stays TypeScript and is compiled to `dist/` (tsup for JS, `tsc` for `.d.ts`, because tsup's dts step injects `baseUrl`, which TS 6 rejects). It is built on `npm install` (`prepare`) and before `dev`/`test`, and watched during `dev`. The client uses the `source` export condition (Vite `resolve.conditions` + tsconfig `customConditions`) and needs no build. | Plain Node cannot import TypeScript. The client keeps full static types from the same schemas. |
| 22  | The Vite dev proxy follows `PORT` from `apps/server/.env` (override: `DEV_API_PROXY_TARGET`).                                                                                                                                                                                                                                                                                          | The server port was changed to 5000 and the proxy silently broke.                              |

## Phase 2

| 25  | Sessions carry a `tokenVersion` (server-only field on the user). Password change and deactivation bump it, revoking other sessions; the current session gets a fresh cookie. Every request re-reads the user, so role and active changes apply immediately.                                                     | Stateless JWTs cannot otherwise be revoked.                                                                    |
| 26  | Login rate limit counts failed attempts only (`skipSuccessfulRequests`). Unknown emails still run a bcrypt compare against a dummy hash.                                                                                                                                                                        | A busy clinic is never locked out; no user enumeration by timing.                                              |
| 27  | Settings are readable by every signed-in role and writable by `admin` only. The users page is admin only. You cannot disable or delete yourself, and the last active admin cannot be demoted, disabled or deleted.                                                                                              | Avoids locking the clinic out of its own app.                                                                  |

The menu is a WAI-ARIA menu button.                                                                                                         | Accessibility without a UI library.                                                                            |

| 33  | Native `<input type="time">` follows the browser/OS locale (it may show AM/PM). Values are always stored as `HH:mm`.                                                                                                                                                                                            | Replacing the native control is not worth it yet.                                                              |

## Phase 9

## Known issues

- `npm audit` reports 2 moderate advisories in `react-router@6` (open redirect via backslash
  paths in `<Link>`/`navigate`; SSR hydration). They are fixed only in v7.18+. The app never
  navigates to user-supplied URLs and does not use SSR. Revisit if moving to v7.
